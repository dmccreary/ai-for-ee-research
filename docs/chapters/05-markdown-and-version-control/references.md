# References: Markdown Project Files and Version Control

1. [Markdown](https://en.wikipedia.org/wiki/Markdown) - Wikipedia - Covers the history, syntax, and variants such as CommonMark and GitHub Flavored Markdown. Relevant to the chapter's headings, lists, tables, and code blocks, and shows side-by-side source and rendered syntax examples.

2. [Git](https://en.wikipedia.org/wiki/Git) - Wikipedia - Describes Git's history, distributed design, core commands, and hosting services. Relevant to the commit, branch, and GitHub repository concepts, with a clear account of how snapshots and branches are stored.

3. [Version control](https://en.wikipedia.org/wiki/Version_control) - Wikipedia - Explains why systems record every change to a set of files, with terminology for commits, branches, merging, and history. Relevant to the chapter's argument that any earlier project state must be recoverable and comparable.

4. Pro Git (2nd Edition) - Scott Chacon and Ben Straub - Apress - Teaches Git by explaining that it stores a stream of snapshots rather than file-by-file deltas, then builds commits and branches on that model with diagrams. This clarifies why commits are cheap and branches are lightweight.

5. The Pragmatic Programmer: Your Journey to Mastery (20th Anniversary Edition) - David Thomas and Andrew Hunt - Addison-Wesley - Its "The Power of Plain Text" section argues for keeping knowledge in plain text and under version control. This supports the chapter's rule that the source is plain text and binaries are build products.

6. [What is Git? (Pro Git, Section 1.3)](https://git-scm.com/book/en/v2/Getting-Started-What-is-Git%3F) - Git SCM - Official free online text contrasting snapshots with delta-based version control, and describing the modified, staged, and committed states. Relevant to the working loop of status, add, and commit, with explanatory diagrams.

7. [CommonMark Specification](https://spec.commonmark.org/) - CommonMark - The standardized Markdown specification by John MacFarlane, with versioned releases. Relevant as the authoritative definition of heading, list, and code-block rules, and it includes executable examples showing source and output.

8. [AGENTS.md](https://agents.md/) - AGENTS.md project - Introduces AGENTS.md as an open, tool-neutral "README for agents," with a sample file covering setup commands, code style, and testing steps. Directly relevant to writing project goals, conventions, and constraints.

9. [How Claude remembers your project](https://code.claude.com/docs/en/memory) - Anthropic Claude Code Docs - Official guidance on writing CLAUDE.md files, using an existing AGENTS.md, and keeping instructions specific and concise. Relevant to project instruction files, with examples of what to include and how files are loaded.

10. [About GitHub and Git](https://docs.github.com/en/get-started/start-your-journey/about-github-and-git) - GitHub Docs - Official introduction to how GitHub builds on Git, covering hosted repositories, collaboration, and review. Relevant to the GitHub repository concept and the push-and-review workflow, with pointers to starter guides.
