## Communicating Research

**Research communication** is the transfer of a result and its reasoning to a particular audience for a particular purpose. The same result is communicated differently to a reviewer, who wants evidence and limits, to a colleague who wants the method, to a student who wants the idea, and to a funder who wants significance. The medium follows from the audience, and agents can help with several of them.

A **slide deck** is the standard medium for a talk. An agent drafts a deck quickly from a paper, and the common failure is a deck that mirrors the paper's structure instead of a talk's. A talk has one message, a few supporting points, and few words per slide. Ask for the deck from a stated audience, time, and single message, and require that each slide state its point as a sentence in the title. Reuse figures from the paper's source scripts and not screenshots, and run the number check of Chapter 15 on every slide, since figures in slides are copied and changed more often than anywhere else.

A static figure shows a result at the parameter values the author chose. An **interactive simulation** is a program that lets the viewer change parameters and see the response, and so lets the viewer explore the relationship the result describes. It is the right medium when the point of the result is a *dependence*: how ENOB falls as noise rises, how leakage changes with window choice, how a search converges. It is the wrong medium for a fact that has no parameter.

## MicroSims

A **MicroSim** is a small, single-concept, interactive simulation that runs in a web browser, is embedded in a page, has open and readable source code, and is built from a short specification. The idea, developed in the author's MicroSims project, is that a simulation small enough to specify in a page can be generated by an AI model, checked by a person, and embedded anywhere that displays web pages. This book contains many, each in its own directory under `docs/sims/` with a `main.html` that is embedded in the chapter and an `index.md` lesson page.

The library most often used is **p5.js**, a JavaScript library for drawing and interaction in the browser. It needs no installation, runs everywhere, and has built-in controls such as sliders, buttons, and drop-downs. The rule in this book is to use the library's own controls and not to draw them by hand, since the built-in ones are accessible and consistent. Two further conventions keep sims embeddable: the first statement in `setup()` reads the container width so that the canvas fits the page, and the canvas is attached to the page's `main` element.

Before the code, here is the relationship it shows. When Gaussian noise of standard deviation \( \sigma \), measured in least-significant bits, is added to an ideal \( N \)-bit quantizer whose own quantization noise has standard deviation \( 1/\sqrt{12} \) LSB, the effective number of bits becomes

\[
\text{ENOB} = N - \tfrac{1}{2}\log_2\!\left(1 + 12\,\sigma^2\right).
\]

For \( N = 10 \) and \( \sigma = 2 \) the value is 7.19 bits, the number used in Chapter 13. The sketch below draws one bar for ENOB and one for the nominal bits, and a slider changes \( \sigma \). It uses `createSlider(min, max, value, step)`, which creates a slider with a minimum, a maximum, a starting value, and a step size.

```javascript
let sigmaSlider;
let canvasWidth = 400;

function updateCanvasSize() {
  canvasWidth = document.querySelector('main').offsetWidth;
}

function setup() {
  updateCanvasSize();
  const canvas = createCanvas(canvasWidth, 220);
  canvas.parent(document.querySelector('main'));
  sigmaSlider = createSlider(0, 4, 1, 0.25);   // noise in LSB
  sigmaSlider.parent(document.querySelector('main'));
}

function draw() {
  background('aliceblue');
  const sigma = sigmaSlider.value();
  const enob = 10 - 0.5 * Math.log2(1 + 12 * sigma * sigma);
  const scale = (canvasWidth - 40) / 10;             // pixels per bit
  fill('lightgray'); rect(20, 40, 10 * scale, 40);   // nominal 10 bits
  fill('steelblue'); rect(20, 110, enob * scale, 40);
  fill(0); noStroke();
  text('Nominal: 10 bits', 20, 30);
  text('ENOB: ' + enob.toFixed(2) + ' bits at sigma = ' + sigma + ' LSB', 20, 100);
}
```

Slide the control to 0 and the bar reaches about 10 bits; slide it to 2 and it falls to about 7.2. A reader who has seen this does not need the formula explained. The same sketch, with labels and a lesson page, is a complete MicroSim.

## Generating a MicroSim With an Agent

**MicroSim generation** is the use of an agent to build a MicroSim from a specification. The workflow of this book is specification first. A specification states what the learner must be able to do afterward, the evidence that shows it, the full content, the rules the model must obey, the activity, and the feedback. It deliberately leaves out layout and code, which the generating agent decides. You have already seen the form: each interactive in the chapters of this book has such a specification in a collapsed block above it, with a Bloom level and verb, an objective, evidence of mastery, content, rules, learner activity, feedback, and chapter anchors.

The workflow has five steps, and the checks matter more than the generation.

1. *Specify.* Write the objective with one verb, the evidence of mastery, and every item of content with its correct answer. If you cannot write the evidence, the sim has no purpose yet.
2. *Search before building.* Look for an existing MicroSim that already teaches the concept. Reuse is cheaper than generation.
3. *Generate.* Give the specification to the agent, with the conventions above. Ask for the code in the standard directory layout.
4. *Verify.* Run it. Check each rule in the specification against the behavior: the formulas, the thresholds, the feedback texts, the boundary cases. A sim that looks right and computes a slightly wrong number is the worst outcome, and the checks of Chapter 13 apply.
5. *Approve.* A person tests the controls and decides that it is ready for learners. In this repository a lesson page carries a `status` value that shows in the navigation: `scaffold` for a specification with no implementation, `built` for an implementation awaiting review, `instrumented` for one that records learner events, and `approved` for one the author has tested. Agents may set the first three. Only the human author sets `approved`.

!!! mascot-tip "Write the Evidence of Mastery First"
    ![Volt offering a tip](../../img/mascot/tip.png){ class="mascot-admonition-img" }
    Before you describe the sim, write one sentence that begins "The learner shows they understand by...". If the sentence names something the sim can check, such as a number entered, a prediction committed, or an item sorted, you have the spine of the activity. If it says "explores", the sim will be a toy.

## Embedding, Concept Dependencies, and Intelligent Textbooks

**Embedding simulations** is placing a MicroSim in a page, normally with an HTML `iframe` element that points at the sim's `main.html`. An iframe isolates the sim from the page, which is also a safety property: the sim's code cannot reach the rest of the page. The chapter pages of this book embed their sims with a relative path such as `../../sims/<sim-id>/main.html` and add a link to open the sim fullscreen. The same sim can be embedded in a slide deck, a course page, or a paper's supplementary website without change. When you cite a sim in a paper, give its published address, and include the repository name in the address so that it can be found.

A **concept dependency** is the relation that one concept must be understood before another can be. A **learning graph** is a directed acyclic graph of concepts in which each edge is a concept dependency. It is the structure that decides the order of a course and, with the chapter's concept impact scores, how much space each concept deserves. This book is organized by one, and its chapters are the groupings of the graph's concepts in dependency order. An **intelligent textbook** is a textbook whose content is interactive and, at higher levels, responsive to the reader. The author's classification of intelligent textbooks distinguishes five levels: static text (level 1), interactive content with MicroSims and learning graphs (level 2), adaptive content driven by student goals and progress (level 3), conversational tutoring (level 4), and autonomous generation of personalized instruction (level 5). This book sits at level 2, and it is organized so that the skills and records needed for level 3 could be added. Level 3 and above require storing student records, which raises privacy questions that the classification flags as a threshold.

**Teaching from research** is turning a result into instruction. The procedure follows the structure of this chapter. Choose one concept from your paper that a newcomer needs. Write the objective and the evidence of mastery. Check the catalog for an existing sim. Specify the one you need, build and verify it, and write a short lesson page that states the prerequisite, the activity, and what the learner should notice. The same sim then serves your talk, your group's onboarding, and your supplementary materials, and a result that others can manipulate is a result that others can build on.

## Summary and Key Takeaways

Communicating a result well is choosing the medium that matches the point. When the point is a dependence, an interactive that lets the reader move the parameter does what a static figure cannot, and an agent can build it quickly from a precise specification that you check.

The main points to carry forward:

- **Research communication** is shaped by the audience. A **slide deck** carries one message and needs a number check.
- **An interactive simulation** suits a dependence or a process, and not a fact.
- **A MicroSim** is small, single-concept, embeddable, and readable. **p5.js** with built-in controls is the usual library.
- **MicroSim generation** is specification first: evidence of mastery, content, and rules, then search, generate, verify, and approve. Only a human marks a sim approved.
- **Embedding** is an iframe with a relative path, and the sim is reusable across decks, pages, and papers.
- **Concept dependencies and learning graphs** order a course, and **intelligent textbooks** range from static to autonomous, with student data privacy rising at the adaptive level.
- **Teaching from research** turns one concept of a paper into an objective, a sim, and a lesson page.
